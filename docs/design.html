Expman Design

Expman is a local web application for exploring TensorBoard logs alongside the YAML configurations that produced them. It should help researchers compare experiments, average repeated runs, and investigate relationships between experimental conditions and logged outcomes. Python dependencies, packaging, and execution are managed with uv.

RuntimeOne uv-managed Python service
Data sourceTensorBoard events and YAML
ReferenceHoloMotion experiment logs

Requirements

Capability Expected behavior
Experiment discovery Discover experiments beneath a configured log directory, including nested event directories and directory aliases.
TensorBoard functionality Provide the actual TensorBoard interface for standard plugins rather than limiting the application to custom scalar charts.
Scalar exploration Compare selected runs with interactive charts, smoothing, axis controls, refresh, and exports.
YAML comparison Show selected experiments side by side, with searchable configuration paths and a differences-only mode.
Configuration exclusions Persist ignored configuration paths and file exclusions; restore them through the UI.
Grouped curves Create named groups or group by configuration values, and show means with explicit variability bands.
Condition analysis Relate numeric and categorical configuration values to a selected metric and outcome definition.
Correlated events Detect spikes or abrupt changes across metrics within one experiment, inspect their chronological order, and measure lead/lag relationships.
Periodic behavior Discover candidate cycles, inspect their stability, and compare periods and phase across metrics.
Experiment management Support names, tags, notes, favorites, and archiving without modifying experiment files.
Local operation Run with uv, serve frontend assets locally, and keep experiment data on the host.

Distributed experiment execution, training control, hosted accounts, and artifact registries are outside the initial scope. Existing logs require no instrumentation changes.

Reference dataset

Use /data/weixu/log/holomotion for development and acceptance testing. Its layout includes:

holomotion/
  exp081/
    config.yaml
    events.out.tfevents.*
    <timestamp>/events.out.tfevents.*
    <timestamp>/hparams.yml
  exp000 -> /horizon-bucket/.../holomotion
  experiments.json
  README.md

An initial discovery pass found 76 candidate experiments. A sample read of exp081 found 1,435 flattened configuration fields, 88 scalar tags, and more than 65,000 scalar points. These observations establish a realistic workload, not fixed counts: experiments and logs can change while the app runs.

Configuration views must handle more than a thousand fields through search and row virtualization or pagination. Discovery must distinguish experiment directories from timestamped logging subdirectories and auxiliary evaluation folders. JSON summaries and the dataset README are supplemental context; event files and YAML remain the authoritative inputs.

Architecture

Use one Python service with a bundled browser application. This keeps installation and startup within uv and avoids a separate Node build requirement.

Component Responsibility
pyproject.toml, uv.lock Package metadata, CLI entry point, dependency groups, and reproducible resolution.
src/expman/cli.py serve and deterministic example-data commands.
src/expman/app.py HTTP API, validation, static assets, and application lifecycle.
src/expman/experiments.py Discovery, stable identifiers, incremental event reading, and summaries.
src/expman/configs.py Safe YAML parsing, configuration provenance, exclusions, and comparisons.
src/expman/analytics.py Curve alignment, aggregation, and descriptive statistical analysis.
src/expman/store.py Atomic persistence of annotations, groups, and preferences.
src/expman/native.py TensorBoard integration and lifecycle management.
src/expman/static/ HTML, CSS, and browser JavaScript shipped in the Python wheel.
tests/ Deterministic ingestion, API, statistical, and integration tests.

Use FastAPI and Uvicorn for HTTP, TensorBoard for event compatibility, PyYAML for safe loading, NumPy for numerical operations, and Plotly for interactive charts. Serve Plotly's bundled JavaScript from the installed Python package so charts do not depend on a CDN.

Mount TensorBoard beneath /tensorboard/ on the same origin. Its own plugins provide scalars, images, histograms, distributions, text, graphs, embeddings, audio, and other supported logged data. Plugin availability depends on installed plugins and the data present. Verify asset URLs and plugin endpoints behind the mount, and manage ingestion workers during startup and shutdown. TensorBoard's broader visualization role is described in its official guide.

User interface

Give Expman's dropdown selectors a search field inside the open menu. Match any part of an option label without regard to case, including the full configuration path in Condition and outcome. Commit a choice with a click or Enter and allow arrow navigation and Escape dismissal. Opening, typing, or dismissing the search leaves the selected setting and the current plot in place. Use the existing selector events when a choice is committed. Keep menus within the viewport, including dropdowns inside modal dialogs.

Use a persistent workspace sidebar, a searchable experiment table, and six main views:

  1. Overview: selected-run chips, metric panels, grouping controls, smoothing, and axis settings.
  2. Experiments: sortable runs with configurable metric and configuration columns, tags, favorites, notes, and archive controls.
  3. Configurations: side-by-side values, a chosen baseline, differences-only filtering, configuration search, and exclusion management.
  4. Relationships: outcome selection, ranked associations, condition plots, and parallel coordinates.
  5. TensorBoard: embedded native TensorBoard with an option to open it separately.
  6. Time series: a single-experiment investigation of spikes, dips, abrupt changes, event timing, periodic behavior, and phase relationships across metrics.

In All panels, organize scalar tags into nested sections using each /-separated prefix, such as Train and Train/loss. Each section shows its matching panel count and can collapse independently. Exclude collapsed descendants from chart requests and persist collapsed prefixes in the log directory's saved view. Provide Expand all and Collapse all controls, show all expanded plot cards, and load viewport batches with at most 32 chart tags per request.

Provide one Overview panel-size control with Small, Medium, and Large presets that change chart height and responsive panel width across all sections and pages. Put a Log Y toggle on each metric panel and persist its scale by tag. Each panel has an Expand button that opens a large dialog with the same data, current zoom, and its own synchronized Log Y control; closing it returns to the overview. Resizing, scale changes, and expansion reuse loaded chart data. Save size and scale preferences in the log directory's view, and migrate an older global Log Y preference to the saved panels.

Compute Overview smoothing in the browser from cached raw observations, using TensorBoard 2.20's bias-corrected EMA. Initialize the accumulator to zero, count finite observations, divide by one minus the smoothing weight raised to that count, and preserve constant and non-finite values. Keep the global slider and numeric input, and give every panel and its expanded view an independent slider and numeric input accepting 0 through 0.999. Changing the global value changes the default for newly displayed panels; an explicit Apply to all panels button copies it to every known panel, including collapsed and off-screen panels. Panel edits do not change global or other panel values. Persist global and per-tag values with the log directory's view. Coalesce slider input to animation frames, reuse raw data without curve requests or full-value job invalidation, and preserve colors, visibility, and zoom.

Return raw member observations, indexed run origins, and group membership through an optional client-smoothing curve response. Smooth each experiment before axis deduplication, interpolation, group aggregation, variability bands, and display sampling. Recompute group means, counts, original means, elapsed times, and bands in the browser without extrapolation; retain every original observation when loading all values. Align backend smoothed configuration and outcome summaries with the same bias-corrected EMA on full histories. Older server responses remain readable and identify when a restart is required for browser smoothing.

Apply the shorter smoothing inputs in expanded views while keeping global controls unchanged.

Handle flat signals, monotonic trends, sparse logs, long gaps, irregular sampling, isolated spikes, and too-short windows explicitly. Flag aliasing risk, limited resolution, shared periodic logging schedules, and sensitivity to the chosen time window. Sampling or computational limits must be visible, and exports must include timestamps, detrending, search bounds, and analysis settings.

The generalized Lomb–Scargle reference describes sinusoidal fitting with uneven timestamps and a floating mean; the periodogram reference provides the regularly sampled counterpart.

Persistence and data access

Keep log-directory-specific annotations, named groups, named filter sets, exclusions, selected runs, collapsed panel prefixes, chart views, and time-series settings in <logdir>/.expman/state.json. On first use of a missing default workspace file, copy only the matching workspace from the previous working-directory .expman/state.json or user-directory state.json. Preserve the source as a backup and never replace an existing destination. Import earlier browser view preferences into workspace state after a successful server save.

Treat TensorBoard event files and source YAML as read-only; save workspace metadata in the dedicated .expman directory. Renaming and archiving affect app metadata, not experiment paths. Never delete logs or rewrite source YAML. Use safe rendering for names, notes, tags, and config values. Bind to 127.0.0.1 by default; remote access should use SSH forwarding or a deliberate authenticated deployment. Do not expose an arbitrary file-read endpoint.

Export raw scalar CSV, comparison or analysis tables, chart images, and workspace metadata. Exports should identify metrics, units, aggregation settings, and exclusions. Raw exports retain unsmoothed values.

# Expman

A local experiment workbench for TensorBoard event logs, YAML/JSON configurations, and JSON summary metrics.

See [the design](docs/design.html) for the architecture, user workflows, data semantics, and acceptance criteria. Open the HTML file in a browser; it includes navigation, a diagram, and print styling.

## Quickstart

Python 3.11 or later and [uv](https://docs.astral.sh/uv/) are required. Dependencies and the frontend are packaged together; no Node build or external chart CDN is needed.

```bash
uv sync --locked
uv run expman demo --logdir experiments/demo
uv run expman serve --logdir experiments/demo
```

Open `http://127.0.0.1:8000`. To inspect your own experiments, use `uv run expman serve --logdir /path/to/logs`. The example includes YAML configurations, scalar curves, delayed spikes, a known periodic signal, images, histograms, text, audio, a graph, and embeddings. Generation refuses to overwrite a nonempty directory.

## Run with HoloMotion logs

```bash
uv run expman serve --logdir /data/weixu/log/holomotion --host 0.0.0.0
```

Open `http://<host-ip>:8000`. Omit `--host` to listen on `127.0.0.1` only. The app has no authentication; use a trusted network or authenticated proxy for shared access. `--port` changes the port. Workspace data defaults to `<logdir>/.expman/state.json`; `--state-file` overrides it. User-wide settings default to `~/.expman/settings.json`; `--user-data-dir` or `EXPMAN_HOME` overrides that directory.

TensorBoard and Overview default to `--tensorboard-loader fast` and share its native data server. Startup reports an error if that reader is unavailable. Explicit `auto` and `python` modes remain available for native TensorBoard compatibility; Overview requires the fast reader. Its status banner identifies the reader. Data can appear while the initial scan continues.

## Workflows

- **Overview:** click **All panels** to browse every scalar metric in nested sections by `/`-separated tag prefix. Collapse individual sections, or use **Expand all** / **Collapse all**. Use **Panel size** to change the width and height of all charts with Small, Medium, or Large presets. Each panel has its own **Log Y** toggle and an **Expand** button for a large dialog; close it or press Escape to return. Size, scale, and expansion reuse loaded chart data. Size and per-metric scales are saved with the workspace. Filter by tag and expand sections to load their plots automatically; collapsed sections skip chart loading. Custom subsets support 8, 16, or 32 panels per page. **Choose panels** supports a custom subset and bulk selection of matching tags. Compare individual runs, selected-run means, saved groups, or groups defined by configuration fields. Zoom, export, change axes, and adjust smoothing.
- **Experiments:** search names, tags, and config values; add typed configuration filters; sort and load result summaries; edit names, notes, favorites, tags, and archive state. Create named filter sets containing multiple conditions, then use **Apply view** or **Select matching**. The latter replaces the selection with matching unarchived experiments. **Clear all filters** resets search, conditions, the active named filter, and the collection to All experiments, preserving selected runs and saved filter definitions. Add configuration columns and choose a baseline for result deltas.
- **Configurations:** display each selected experiment on one row, with configuration and scalar fields in value-sized columns with multiline headers. Compare only selected experiments, choose and save the baseline, and highlight configuration differences in customizable green. Path text is selectable; drag header grips to reorder columns, or focus a grip and press Alt+←/→. Use the header checkbox to include or ignore a configuration, or Manage exclusions for YAML filenames. Add scalar rows using Latest, Latest smoothed, Value at step, or Smoothed value at step. Scalars have independent None/Largest/Smallest highlighting with a customizable pink color; ties are included. Configuration values appear immediately while scalar rows load with progress. **Full names** beside the path header switches to full configuration paths. Drag header separators to resize columns, or focus one and use ←/→ (Shift for larger steps); the reset icon restores automatic fitting. Names and widths are saved per workspace. Scalar cells without data stay empty. The compact table keeps cell text on one line with ellipses and full-text tooltips to fit more experiments; pagination, path search, and CSV export support larger comparisons.
- **Relationships:** Automatic inherits the first configured scalar field's metric, summary mode, target step, and smoothing, respecting Configurations column order. Choose explicit metrics or summaries to override it. Association ranking defaults to Configurations' differences and path-search filters; choose **All configs** to include every non-excluded path. The score labels link to Wikipedia explanations. Parallel coordinates connects each experiment's conditions and outcome; missing conditions have labeled positions and retain their lines. **Dimensions** shows field coverage, **Reset dimensions** chooses varying fields, and **Clear brush** removes ranges. Drag vertically on an axis, then explicitly adopt brushed runs. Computation has progress, Cancel, and visible errors with Retry. Final values reuse the fast index; history-based summaries reuse complete observations for the chosen metric. Exports include step and smoothing settings; the first step is empty for final-only reads. String conditions remain categorical, and dot tooltips show experiment names and metric values.
- **Time series:** choose one experiment; analysis includes **all scalar curves by default**. Narrow it with inclusion/exclusion globs, one per line: `Loss/*`, `*reward*`, `Metrics/Task?`; exclusions take priority and matching is case-sensitive. Start analysis to see stage progress, the current metric, elapsed time, and cancellation. **Account for periodic fluctuation** is enabled and saved by default. Reliable cycles use a baseline for the expected cycle phase and normal variation between cycles, so routine peaks are separated from unusual spikes; turn it off to use local scoring only. Expand the cycle summary to see inferred periods and adjustment coverage. Periodic behavior retains unadjusted repeated-event intervals. Boundary scores allow for local startup variation without discarding early steps, and aligned-chart tooltips keep each curve's values on one line. Detect spikes, dips, or abrupt changes; inspect event order, nearby matches, and lagged correlations. Positive delay means the target follows the reference. Choose a reference or let Expman select one with activity. Browse results eight curves at a time; JSON and event CSV exports include all results.
- **Periodic behavior:** within Time series, select the periodicity investigation to explore candidate periods, autocorrelation, repeated-event intervals, common-period phase delays, and optional moving-window spectra. Export results and settings as JSON.
- **TensorBoard:** open the native interface for available scalar, image, histogram, distribution, text, graph, audio, and embedding plugins. The interface opens while background indexing proceeds; a status banner identifies the reader and available streams. The fast reader streams results during ongoing indexing. The Python fallback reports discovered streams and elapsed time, and can take more than 20 minutes on gigabytes of events. Plugin visibility depends on logged data and installed plugin support.
- **Appearance:** use the top-bar button to customize fonts, size, text/background/surface/accent/border colors, or apply a preset. Text defaults to black. Settings apply to custom views and charts; native TensorBoard controls its own appearance.

Selection is shared across comparison views. Filters preserve the selection and show when selected runs are hidden. Time-series investigations use their own single-experiment selector. Refresh manually or enable the 30-second automatic refresh.

The experiment search also filters Overview curves as you type, matching names, paths, tags, and configuration values without case sensitivity. Overview plots matching selected experiments and shows how many selected runs are hidden by the search or filters. Clearing the search restores their curves while preserving selection. Group means and per-panel full-value reads use the same matching subset; searching does not reload metric discovery.

Overview panels show how many selected experiments have plotted data. Expand the explanation below a panel to see which experiments lack scalar logs, did not record that metric, are still indexing, or are outside the chosen groups. Identical curves can overlap. The difference table uses vertical cell borders and the shortest unique suffix for both configuration paths and scalar names. Scalar suffixes use `/` separators, keeping enough parent segments to distinguish matching names and preserving units such as `(m/s)`. Hover for the full path and scalar summary settings; **Full names** restores complete labels. Labels remain consistent across table pages and searches.

Overview uses TensorBoard's bias-corrected exponential smoothing in the browser. Each panel has its own slider and numeric box (`0`–`0.999`), also available in its expanded view. The **Global smoothing** value is the default for new panels; click **Apply to all panels** to copy it to every panel, including collapsed and off-screen panels. Panel edits remain independent. Settings are saved per log directory. Smoothing edits reuse loaded observations and preserve full-value reads without fetching curves again.

In **All panels**, expanding a tag section reveals its plots immediately. Off-screen plots load automatically as you scroll, with bounded request batches and caches. There is no second **Show these panels** step. Custom panel subsets retain pagination.

One shared legend stays visible while scrolling Overview and controls every plot. Long legend lists scroll within the legend. Click an experiment's name to show or hide its curves across panels, double-click to isolate it, or click its color swatch to choose a different color. Double-click the isolated name again to restore the other curves; **Show all curves** also restores every curve and uncertainty band. Colors and visibility are saved with the workspace and apply across pages and full-value reads without changing experiment selection. Grouped views list each group once. The same legend moves into an expanded plot's dialog and returns when it closes; individual plots have no separate legends. Hover entries show each experiment's name, **Smoothed** and **Original** values, and elapsed time on one line. Original values come from the same loaded observations before smoothing; grouped curves show both values as member means at the displayed position. Elapsed time uses TensorBoard's indexed run start when available, with the first loaded observation as a fallback; grouped curves show mean elapsed time across their contributing experiments. Durations of at least a day include days, for example `1d 02:03:04`. If a panel reports missing original values, restart Expman and refresh to load the backend that supplies them.

Experiment colors are shared by Overview, selection chips, the Experiments table, and Relationships outcome dots. The 32 distinct defaults use lighter and darker variants for larger selections. Selected experiments receive colors first in experiment-path order, so filtering and paging preserve colors. Changing the selection can change automatic defaults; saved custom colors take precedence everywhere and survive restarts. Category box summaries and outcome-magnitude color scales retain their own meanings.

Experiment **Filters**, **Clear all filters**, and named-filter controls share one toolbar row. Clear all filters is disabled when no restriction is active.

Time-series analysis shows submission progress immediately, retrieves completed cached results, and keeps errors visible with retry controls. Threshold accepts finite values of at least `1`, including `50`, and applies to the absolute **Event score**. Continuous curves use the local median/MAD **Robust score**, measuring each window's variation around its own median. Exact 0/1 curves use a smoothed Bernoulli score with a separate **Binary context**, defaulting to 1,001 logged observations; this prevents ordinary flag changes from receiving scores such as 1e9. Change the binary context independently of the continuous window. Both models use available observations at log boundaries, without repeated endpoint padding. **Display z-score** uses the displayed curve's mean and standard deviation. Aligned-chart tooltips keep each curve on one line; event entries show only kind, raw value, and score. Full scoring context remains in result tables and exports. Event rows and CSV exports sort by absolute Event score, strongest first; metrics are browsed by their strongest event. The timeline chart retains time positions.

In Overview, **Ignore outliers in chart scaling** chooses the Y range from the middle 90% of finite plotted values. It supports linear and logarithmic panels, expanded charts, and chart resets. The option is saved with the workspace and updates loaded charts without fetching curves again. All observations, calculations, and exports remain available; uncheck it to restore the full Y range.

Overview always loads curves through the fast reader and labels retained samples. Each panel has a **Load all values** action with progress and cancellation. It uses a temporary native reader retaining every scalar observation and applies only to that panel and current selection, axes, and grouping; smoothing changes reuse the result. **All values loaded** appears after the plot redraw succeeds; a failed redraw shows a retry action that reuses the loaded observations. Full-value reads are not saved across page reloads. Configurations and Relationships use the same bias-corrected smoothing formula on full histories, so retained-sample Overview curves can still differ until all values are loaded. Named experiment filters can combine configuration conditions and **Experiment path** predicates, including Contains, Does not contain, and Matches glob on paths relative to the log root, such as `*/exp07*`. Contains and Does not contain compare literal substrings without case sensitivity; use Does not contain with `debug` to exclude paths containing that text.

## Data semantics

Experiments are discovered recursively. Directory aliases are deduplicated, cycles are avoided, and broken links are reported. Event streams under an experiment are namespaced by their relative directory. Both legacy scalar summaries and tensor-backed scalars are supported; repeated surviving steps retain the latest observation. Cached scalar arrays are compact and evicted when the point budget is exceeded.

The primary configuration is `config.yaml`, `config.yml`, or `config.json`, in that order, with `.hydra/config.yaml`, `.hydra/config.yml`, and `.hydra/config.json` as fallbacks. Other root YAML/JSON files and timestamped `hparams.yml`, `hparams.yaml`, or `hparams.json` files use file-qualified paths such as `@extra.json::optimizer.lr`; they never silently overwrite the primary config. Literal dots and backslashes in keys are escaped. Loading is safe, and Hydra expressions remain literal. Malformed files retain source text and warnings. Missing configuration cells are blank; explicit null is displayed as `null`. Typed comparisons still distinguish missing, null, boolean, numeric, and list values.

**JSON metrics** configures additional numeric summaries. By default, Expman discovers `{experiment}/evaluation_metrics.json`. Supply one filename or path per line: `evaluation_metrics.json` reads that file inside every experiment, and `{experiment}/evaluation/metrics.json` reads a nested file. A bare filename always refers to experiment files. Files accept `{"accuracy": 0.9}`, `{"metrics": {"accuracy": 0.9}}`, or an evaluation record with `experiment`, `status`, and `metrics` fields. The experiment folder identifies the owner, including older experiment aliases. Nested numeric names are joined with `/`, under a source prefix such as `JSON/evaluation_metrics/Success rate`. Metric choices are populated from selected experiments before TensorBoard indexing finishes.

Loading shows file progress, saving, and configuration discovery. Invalid sources leave the previous registrations active. Paths are saved in `<logdir>/.expman/state.json` and restored on startup; **Refresh** reloads changed values. Remove all paths to disable imports. Imported summaries are selectable in Configurations → **Add scalar** using **Latest**, and Relationships → **Outcome metric** using **Final value**. They are excluded from configuration conditions and curve panels. Missing or pending metrics leave blank cells; JSON summaries do not invent steps or smoothing histories.

Exclusions support exact paths, subtrees, and glob patterns such as `seed` or `paths.*`. For configuration files, a bare filename or filename glob such as `hparams.yml` or `hparams.*` matches at any directory depth. Patterns containing `/`, such as `123/hparams.yml` or `*/hparams.yml`, match experiment-relative paths. Exclusions affect config comparisons, configuration grouping, and relationship analysis. Registered JSON metric sources are excluded from configuration discovery. Restore exclusions in **Manage exclusions**. **Show ignored** intentionally includes excluded rows in the comparison.

Each configuration column has an inclusion checkbox: checked means included, unchecked means ignored. Uncheck a field to ignore it; enable **Show ignored** and check it to add it back directly. Changes save immediately and in order, and cached responses cannot restore ignored rows. Adding a row back removes matching path and filename exclusions, including subtree and glob rules, so other configurations covered by those rules are also restored. **Manage exclusions** remains available for editing patterns in bulk.

The configuration table has synchronized horizontal scrollbars above and below its rows. Multiline configuration/scalar headers stay pinned during vertical scrolling, and experiment names stay pinned horizontally. The top scrollbar updates after column or viewport resizing; cached row updates preserve scroll position. App scripts and styles revalidate on reload; after updating a page that was already open, use a hard refresh to load the latest controls.

Group means interpolate within recorded ranges. Common overlap is the default; union mode reports varying contributor counts and never extrapolates. Bands can show population standard deviation, min–max, or sample standard error; the latter needs two contributors. Smoothing affects charts only. Raw CSV and outcome analysis use unsmoothed values.

Associations and temporal relationships are descriptive, not causal. Numeric association uses absolute Spearman correlation; categorical association uses square-root eta squared. Periodic fits use recorded timestamps, a configurable trend model, and at most 4,096 disclosed observations per curve. Candidate peaks are not significance probabilities. Phase delays are modulo one cycle. Large gaps are masked in resampled correlation views, and logging cadence limits timing precision.

In Relationships → **Condition and outcome**, choose **Type → Categorical** to group distinct numeric values. **Include missing as a category** is optional and off by default. When enabled, **Merge missing and null** defaults to on, producing one `(missing or null)` group; uncheck it to keep the groups separate. Numeric conditions with included missing values use categorical groups. These settings apply to association scores and chart axes and are saved separately for each condition and log directory.

Annotations, manual groups, named filter sets, exclusions, selected runs, collapsed tag prefixes, chart views, and time-series settings are atomically stored in `<logdir>/.expman/state.json`. User-wide appearance and automatic-refresh preferences are stored separately in `~/.expman/settings.json`. Browser preferences from earlier versions are imported into workspace state on first use, then removed from browser storage after a successful save. Archiving and renaming affect metadata only; Expman does not delete event logs or rewrite experiment configs.

Time-series jobs run on one background worker to limit contention. Identical requests reuse results until event-file identities, sizes, or modification times change. Completed results expire after 20 minutes and are limited to four jobs and a 64 MiB budget, retaining one oversized result if necessary. Numerical fits process frequency blocks, correlations use vectorized overlap statistics, and chart browsing limits drawing work without limiting the analysis scope.

Metric discovery, scalar comparison, and full-panel reads use separate background queues, so they do not hold up YAML comparisons. Latest scalar values reuse the shared reader; smoothing and fixed-step summaries use every observation through TensorBoard's native reader. Their history cache is bounded to two selections and 128 MiB, invalidated when event files change. Full reads use the native [`scalars=all` retention setting](https://github.com/tensorflow/tensorboard/blob/master/tensorboard/data/server/cli.rs); display sampling is disabled for the requested panel. Restart the application after backend updates, then refresh the browser.

When the default workspace file does not exist, Expman imports matching log-directory state from the previous working-directory `.expman/state.json` or `~/.expman/state.json`. It copies only that workspace, preserves the original file as a backup, and never replaces an existing destination. Both metadata locations must be writable for saving; `--state-file` and `--user-data-dir` support read-only log roots or custom storage.

## Development

```bash
uv sync --locked
uv run expman --help
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv build
```

The Python package lives in `src/expman/`; bundled assets are in `src/expman/static/`. Tests cover actual TensorBoard event files, config comparisons, persistence, group mathematics, outcomes, event timing, periodicity, and native TensorBoard endpoints. OpenAPI documentation is available at `/docs`, and the HTML design is served at `/design`.

Real Chromium tests live in `tests/ui/` and run against the actual server, bundled Plotly, and native TensorBoard reader with temporary synthetic logs and workspace state. Install the pinned browser tooling and Chromium, then run:

```bash
uv run --locked --with-requirements tests/ui/requirements.txt python -m playwright install chromium
uv run --locked --with-requirements tests/ui/requirements.txt pytest tests/ui --ui --browser chromium --tracing retain-on-failure --screenshot only-on-failure --output test-results
```

On Linux, add `--with-deps` to the installation command if Chromium needs system libraries. The `Browser UI` GitHub Actions workflow installs those libraries and runs the complete backend and browser suite on pushes and pull requests. Failures retain browser traces, screenshots, and JavaScript/application/HTTP error reports in `test-results/`. Tests fail on browser errors or application error toasts, including errors caught by the app itself. To run the complete suite locally, replace `pytest tests/ui --ui` with `pytest --ui` in the command above.

Coverage includes repeated panel expansion and regrouping, independent/global smoothing without curve requests, shared legend isolation and persistent colors, automatic loading after section expansion and scrolling, and navigation through Experiments, Configurations, Relationships, and Time series. A 20,050-observation test checks actual Plotly input traces, calculated steps, and SVG vertices after **Load all values**, smoothing, and repeated expansion. Full-value plots disable line simplification so every plotted observation remains a vertex.

Ordinary `pytest` runs skip the browser suite; an explicit `--ui` run requires its dependencies and never silently skips a missing installation. On November 13, 2026, the complete suite passed **171 tests with no skips**, including six real Chromium tests and the native TensorBoard socket integration. This run used individually approved execution outside the ordinary sandbox, which still denies sockets. Browser dependencies and Chromium were downloaded using that approved route. To reuse the installed temporary caches, prefix both commands with `UV_CACHE_DIR=/tmp/expman-uv-cache PLAYWRIGHT_BROWSERS_PATH=/tmp/expman-playwright`. The [verification record](docs/design.html#verification-status) distinguishes the checks performed from remaining manual coverage.
